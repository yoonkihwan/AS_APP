# TOOL_INVENTORY 개발 명세서 (기존 프로그램 웹 전환)

## 1. 개요
*   **시스템 명:** 장비/툴 입출고 관리 시스템 (Tool & Inventory Management)
*   **목적:** 기존 데스크톱 파이썬 프로그램(`TOOL 입출고 관리.exe`)과 `inventory.db`의 데이터를 웹 애플리케이션으로 전환하여 AS 프로젝트와 같은 서버에서 작동하도록 함.
*   **주요 특징:** 
    * AS 시스템(`as_app`)과는 데이터 통신은 최소화하되, **기준 정보(Brand, Tool)는 공유(Single Source of Truth)**.
    * 화면과 접근 경로는 완전히 격리하여 운영 (다중 Admin Site 구조).
    * 대량의 인라인 UI 처리를 순수 Javascript와 연동 및 실시간 재고 PDF 다운로드 지원.

## 2. 기존 데이터베이스 분석 및 테이블 매핑
기존 프로그램(`inventory.db`)은 매우 직관적인 텍스트 기반의 데이터 구조를 가지고 있습니다. 이것을 장고의 관계형 데이터베이스(PostgreSQL) 형태로 변환하여 구현합니다.

### 2.1 마스터 테이블
기존 데이터베이스엔 단순히 이름만 관리되는 목록들이 있습니다. 이번 프로젝트로 전환하며 **AS 앱(`as_app.models`)의 기준 정보를 사용**합니다.
*   `Brand` (as_app) - 브랜드
*   `Tool` (as_app) - 브랜드별 장비/툴

### 2.2 메인 테이블 (입출고 내역)
*   **Inventory (통합 입출고 이력):** 개별 장비(시리얼 단위) 재고 테이블. 단순 조회용도로만 관리자 뷰에 공개되며 `+` 추가 버튼 등은 비활성화됩니다.
    *   `id`: `UUID` 형태의 기존 고유값. 장고에서도 `UUIDField(primary_key=True)`를 사용하여 기존 ID 유지.
    *   `batch`: 입고 배치 (새로운 연동 구조)
    *   `tool`: AS 앱의 Tool 모델 연동 (Foreign Key)
    *   `serial`: 시리얼 번호 (`CharField`, 선택 입력 가능)

*   **InboundBatch (입고 테이블):** 다수 입력 처리를 위한 래퍼(Wrapper) 
    * 날짜, 공급사, 담당자 헤더 정보 기록.
    * 인라인 모델을 통해 `Inventory`를 다건 생성하고, `,`로 구분된 시리얼 번호를 자동 스플릿.

*   **OutboundBatch (출고 테이블):** 다건 출고 처리를 위한 헤더
    * 날짜, 매출처 헤더 정보 기록.
    * 인라인을 통해 다수 `OutboundTicket` 생성.

*   **OutboundTicket (출고 티켓 데이터):** 특정 툴을 몇 개, 혹은 특정 시리얼을 지정하여 출고
    * 화면에서 `Brand` 선택 시 `Tool` 목록이 비동기로 갱신됨.
    * `Tool` 선택 시 해당 툴에 해당하는 재고 목록(시리얼유/무)이 브라우저 하단에 동적 체크박스로 표시, 수량이 계산됨(FIFO 지원).

### 2.3 프록시 모델 (조회/출력 전용)
*   **ToolStockSummary (재고 현황):** `Tool` 마스터 모델을 상속받아, 현재 `Inventory` 테이블 기준 상태가 '재고'인 데이터를 툴 종류별로 그룹핑합니다.
    * 툴별 **보유 수량** 및 **시리얼 목록** 집계를 한 눈에 확인 가능.
    * 좌측 체크박스 없이 상단에 "재고 내역 출력 (PDF)" 글로벌 버튼이 위치하여 전체 재고 현황을 인쇄용 PDF 파일로 다운로드 받을 수 있습니다.

## 3. 화면 구성 및 분리 원칙 (Admin Site 분리)
AS 관리와 툴 인벤토리 관리를 하나의 서버에서 운영하되, 사용자가 작업 도중 헷갈리지 않게 **접속 경로와 관리자 화면 전체를 분리**합니다.

*   `as.yoursite.com/inventory/`: **툴/장비 관리 시스템** (본 앱 관련 기능만 노출)

본 앱(Tool Inventory)의 Admin 화면은 다음을 충족합니다:
*   **대시보드:** 별도의 독립적인 대시보드를 구성.
*   **메인 관리 화면:**
    *   "통합 입출고 이력 (기존 인벤토리)", "입고 등록", "출고 등록", "재고" 절차 별로 메뉴 분리.
    *   다건 배치를 위해 API 라우팅과 `JS` 파일 (`outbound_form.js`)을 기반으로 빠르고 정확한 조작 확보.

## 5. 바코드 스캐너 연동 설계 (MQ160W 도입 예정) 📌
*   **스캐너 모델:** MQ160W 미라클 스캐너 (유/무선 공용 2.4G/USB)
*   **연동 방식:** USB HID(Human Interface Device) 키보드 에뮬레이션
*   **현장 라벨 현황 (2026-10-26 확인):**
    - **시리얼 번호:** 전 장비 바코드 인쇄 완료 (스캔 즉시 식별 가능).
    - **품명(모델명):** 일부 장비 바코드 미출력 상태.
    - **입고 시 품목 자동화 전략 (2026-11-01 고도화):**
        1) **작업대 툴 마스터 바코드 시트 (강력 권장):** 자주 들어오는 툴 20~30종의 [브랜드+품목 바코드]를 A4 시트로 코팅 비치하여 [품목 바코드 띡] ➔ [박스 시리얼 띡] 2연타로 키보드 조작 없이 1.5초 컷.
        2) **동일 품목 일괄 입고 (선지정 후 연타):** 화면에서 모델 1회 선택 후 박스 5~10개의 시리얼만 연속 스캔하여 쉼표 자동 누적 배치 입고.
        3) **박스 품명 바코드 2-Step 감지:** 박스에 모델 바코드가 있는 경우 자동 인식 후 드롭다운 연동.
        4) **과거 출고 이력 자동 역추적:** 반품/재입고 장비는 시리얼만으로 이전 브랜드/품목 100% 자동 채움.
        5) **에이전트 중복 창 방지:** 현재 웹 브라우저가 입고/출고 폼 화면에 이미 활성화되어 있을 경우 새 탭 팝업을 억제하고 폼 내부 연속 누적 활성화.
*   **핵심 연동 과제 및 기능 로드맵:**
    1. **스캔 입력 인터셉터 (JS Global Listener):**
       - 브라우저 어디서든 바코드 스캔 시 50ms 미만 초고속 입력을 감지하여 전용 버퍼/인풋으로 자동 라우팅.
       - 스캐너의 Enter 접미사(Suffix)로 인한 의도치 않은 Form Submit 차단.
    2. **고속 연속 입고 모드:**
       - 시리얼 바코드 연속 스캔 시 쉼표(`,`) 분리 또는 인라인 자동 추가.
    3. **스캔 다이렉트 출고(피킹) 모드:**
       - 출고처 선택 후 장비 시리얼 바코드 스캔 → 비동기(API) 재고 검증 → 출고 목록 즉시 담기 및 일괄 출고.
    4. **바코드 라벨 인쇄 시스템:**
       - 장고 시스템 내에서 툴/시리얼 바코드 라벨(Code128/QR) 브라우저 인쇄 지원.
    5. **명령 제어 바코드 (Action Barcode):**
       - [모드전환], [저장/확정], [초기화] 제어 바코드 출력 및 핸즈프리 조작 환경 구축.
    6. **웹 미실행 시 자동 호출 및 스마트 분기 에이전트 (`scripts/barcode_agent.py`) ✅:**
       - **동작 방식:**
         * 브라우저가 꺼져 있거나 다른 프로그램 작업 중에도 Windows 저수준 키보드 훅(`ctypes`)으로 스캐너 입력(40ms 이하) 감지.
         * 스캔 즉시 로컬 API(`/inventory/barcode-api/lookup/?serial=...`)로 0.05초 만에 재고 유무 판별.
         * **재고 상태인 장비 스캔 시:** 브라우저를 활성화하며 **[출고 등록]** 화면(`outboundbatch/add/?serial=...`)으로 직행!
         * **미등록/신규 장비 스캔 시:** 브라우저를 활성화하며 **[입고 등록]** 화면(`inventorybatch/add/?serial=...`)으로 직행!
         * `SetForegroundWindow`로 윈도우 포커스를 최상단으로 강제 복원.
    7. **기존 [입고 등록] 및 [출고 등록] 직결 연동 완료 (2026-10-27) ✅:**
       - **사이드바 메뉴 정리:** 별도의 복잡한 '바코드 입출고' 사족 메뉴는 완전 철거하여 기존 메뉴 구조의 단정함 유지.
       - **[입고 등록] 화면 연동 (`inbound_form.js`):**
         * 시리얼 번호 입력창에서 바코드 스캔 시 자동으로 `, `(쉼표)가 연결 누적 (`SN001, SN002, SN003...`).
         * 스캐너의 Enter 키로 인한 폼 자동 제출 차단 및 연속 스캔 보장.
         * 저장 시 백엔드 `InventoryBatch`에서 쉼표 자동 분할로 일괄 입고 완료.
       - **[출고 등록] 화면 연동 (`outbound_form.js`):**
         * 출고 화면 어디서든 바코드 스캔 시 해당 시리얼 체크박스 자동 [체크] 및 출고 수량 자동 +1 카운트.
         * 해당 품목이 화면에 열려있지 않은 경우 API로 품목 자동 식별 후 인라인 폼 자동 선택 및 체크박스 활성화.
    8. **로컬 에이전트 통신 및 세션 도메인 정합성 조치 (2026-11-01) ✅:**
       - **Host 불일치 해결:** 브라우저 접속 주소(`http://127.0.0.1:8001`)와 에이전트 설정(`agent_config.ini`, `barcode_agent.py`)의 `SERVER_URL`을 `http://127.0.0.1:8001`로 일치화 (`localhost`와 `127.0.0.1` 간 쿠키 미공유로 인한 중복 로그인 화면 리다이렉트 방지).
       - **조회 API 인증 래퍼 해제:** `/inventory/barcode-api/lookup/` 엔드포인트에서 `self.admin_view`를 해제하여 백그라운드 파이썬 데몬(`urllib.request`)이 세션 쿠키 없이도 순수 JSON 재고 응답을 즉시 수신하도록 수정 (오프라인 폴백 에러 해결).
       - **입고 등록 URL 정규화:** `tool_inventory` 앱의 입고 배치 모델명인 `InventoryBatch`에 맞춰 엔드포인트를 `inboundbatch/add/`에서 `inventorybatch/add/`로 수정하여 404 라우팅 오류 해결.
    9. **활성 창 감지 및 툴 마스터 바코드 연동 (2026-11-01) ✅:**
       - **중복 탭 팝업 방지 (`barcode_agent.py`):** `user32.GetForegroundWindow()`로 브라우저(입출고 관리 화면)가 이미 전면에 떠 있을 경우 `webbrowser.open` 호출을 원천 차단하여 새 탭이 계속 생기는 현상 해결.
       - **툴 마스터 바코드 규격 (`TOOL:<brand_id>:<tool_id>`):** 작업대 시트의 바코드 스캔 시 웹 화면(`inbound_form.js`)이 감지하여 해당 행의 브랜드와 툴을 1초 만에 자동 선택하고 시리얼 입력란으로 커서 자동 이동.
       - **A4 인쇄용 마스터 바코드 시트 (`/inventory/barcode-sheet/`):** DB 내 등록된 모든 툴(클레코, 에스틱, 요코타, 토쿠 등 9개 브랜드 44종)을 브랜드별로 자동 집계하여 선명한 Code128 바코드 카드로 출력할 수 있는 전용 인쇄 화면 구축 완료.
       - **한글(IME) ➜ 영문 QWERTY 100% 자동 치환:** 스캐너 입력 시 Windows 한글 입력기 상태로 인한 한글 오입력(`ㅒㅐㅣ:1:12`, `ㅅ`)을 초성/중성/종성 분해 알고리즘으로 100% 영문으로 강제 변환.
       - **스캐너 특성 오차 보정:** 대소문자 무시(`tool` ➜ `TOOL`), Shift 누락 세미콜론 보정(`tool;1;1` ➜ `TOOL:1:1`), 하이픈 규격(`TOOL-1-1`) 지원.
       - **브라우저 캐시 버스팅:** `change_form.html`에서 타임스탬프(`?v={{ cache_bust }}`) 파라미터를 강제 주입하여 옛날 자바스크립트가 캐시로 남는 문제 원천 차단.

     10. **툴 마스터 바코드 파싱 치명적 결함 수정 및 한글 IME 원천 차단 (2026-11-01 긴급) ✅:**
        - **원인 분석 (스크린샷 버그 원천 규명):**
          1) `inbound_form.js`에서 `input` 이벤트마다 `/(?:TOOL|OOL):(\d+)(?::(\d+))?/i` 정규식으로 타건 중도 검사를 수행함.
          2) 2번째 그룹이 옵셔널(`?`)이었기에 스캐너가 `TOOL-1-9`를 고속 타건하는 도중 `TOOL:1`까지만 찍힌 시점에 즉각 매칭 성공으로 판정해버림.
          3) 결과적으로 툴 9, 13, 16 등을 찍었음에도 불구하고 모든 행이 `CLECO`(brand 1) > `48EAE41AM3`(tool 1)로 강제 지정되고, 뒤이어 입력된 `-9`, `-16`, `-13`이 시리얼란에 잔류하여 `:9, `, `:16, `, `:13, ` 형태의 기괴한 쓰레기 데이터가 생성됨.
          4) 행에 시리얼 찌꺼기가 차 있으니 다음 스캔 시 매번 불필요한 '행 추가'가 발동하여 행이 무한 증식됨.
        - **조치 내역:**
          1) **`input` 이벤트 중도 가로채기 완전 삭제:** `input` 및 `compositionend` 이벤트에서는 오직 실시간 한글(IME) ➜ 영문 대문자 변환만 수행. 바코드 실행 액션은 원천 차단.
          2) **Enter 키 원자적(Atomic) 완전 검증 체계 확립:** 스캐너의 입력 스트림이 끝나는 `Enter` 키 도달 시에만 `parseToolMasterBarcode`를 실행하여 `TOOL:brand:tool` 2단 완전 규격 및 툴단독 규격을 엄격히 분기.
